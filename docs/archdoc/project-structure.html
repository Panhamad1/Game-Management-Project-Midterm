Unity Project Structure & Asset Organization

The official directory layout, naming standards, and Git version control rules for the four-person REBOUND development team. Designed to prevent merge conflicts, asset clutter, and broken references.

1. The Clean Assets/_Project/ Standard

Standard student projects often dump all scripts, downloaded textures, and test scenes into the root Assets/ folder. When multiple team members import third-party packages, root folders collide and Git merge conflicts become frequent.

REBOUND enforces the industry standard Assets/_Project/ layout. All code, prefabs, materials, and scenes created by the team live exclusively inside _Project/. All external asset packs live isolated in Assets/ThirdParty/: 

Assets/
├── _Project/                          // Team-created game content ONLY
│   ├── Art/                           // Materials, textures, shaders, VFX
│   │   ├── Materials/                 // MAT_Interactable_Glow, MAT_FloorTile
│   │   ├── Models/                    // Modular wall sections, door meshes
│   │   └── VFX/                       // Pull beam LineRenderer, push blast particles
│   ├── Audio/                         // Sound clips and audio mixer assets
│   │   ├── SFX/                       // SND_Push_Blast, SND_Pull_Hum, SND_Reset
│   │   └── Music/                     // Ambient background tracks
│   ├── Prefabs/                       // Reusable GameObject blueprints
│   │   ├── Player/                    // PF_PlayerRoot (Rigidbody + Camera)
│   │   ├── Interactables/             // PF_Crate_Light, PF_Crate_Medium, PF_Block_Heavy
│   │   ├── Environment/               // PF_FloorTile_4x4, PF_WallSection, PF_Ramp
│   │   └── System/                    // PF_ExitDoor, PF_PressurePlate, PF_HazardPit
│   ├── Scenes/                        // Game levels and testing sandboxes
│   │   ├── 00_Boot/                   // MainMenu.unity
│   │   ├── 01_Prototype/              // PrototypeLab.unity (Physics testing playground)
│   │   └── 02_Levels/                 // Level_01.unity through Level_07.unity
│   ├── Scripts/                       // C# modular subsystem code
│   │   ├── Player/                    // PlayerMovement.cs, MouseLook.cs
│   │   ├── Abilities/                 // PullAbility.cs, PushAbility.cs, SlowMotionAbility.cs
│   │   ├── Physics/                   // AbilityTarget.cs (Interactable tag)
│   │   ├── Level/                     // LevelExit.cs, PressurePlate.cs, DoorController.cs
│   │   └── UI/                        // AbilityHUD.cs, ReticleFeedback.cs
│   └── Settings/                      // Unity Input Actions, URP assets, Physics settings
└── ThirdParty/                        // Downloaded packages (Kenney, Quaternius) - DO NOT MODIFY

2. Script Registry & Ownership Mapping

To prevent merge conflicts, each script has a single primary author. Other team members interact with a script exclusively through its public methods and events:

Script File Primary Owner Subsystem Physical Responsibility in the Game
PlayerMovement.cs Person 1 Player Core Controls WASD movement, jumping, ground checks, and applies physics recoil impulses to the Rigidbody.
MouseLook.cs Person 1 Camera Rotates the body horizontally (Yaw) and the camera pivot vertically (Pitch clamped -85° to +85°).
PullAbility.cs Person 2 Abilities Casts ray from origin, targets valid objects, and applies damped spring force towards the holding point (2.5m).
PushAbility.cs Person 2 Abilities Fires impulse blast at target (+12 units) and immediately triggers player recoil (-5 units) even in empty air.
AbilityTarget.cs Person 2 Physics Objects Attached to every movable crate. Defines mass multipliers, whether it can be pulled/pushed, and manages hover glow.
PressurePlate.cs Person 3 Level Mechanics Weighted floor sensor. Detects crate overlaps and invokes UnityEvent to open linked doors.
LevelExit.cs Person 3 Level Progression Exit door sensor volume. Notifies GameFlow to load the next room when the player steps through.
SlowMotionAbility.cs Person 4 Time & Systems Manages the 4-second energy meter, sets Time.timeScale = 0.25f, and syncs Time.fixedDeltaTime = 0.005f.
AbilityHUD.cs Person 4 UI & Presentation Renders crosshair reticle states, slow-motion stamina bar, and push cooldown ring using unscaled time.
GameFlow.cs Person 4 Game State Coordinates room loading, pause screens, player reset on pit falls, and victory completion screen.

3. Asset Naming Conventions

Consistent naming allows the team to find assets quickly using Unity's project search bar without clicking through nested folders:

Asset Type Prefix Naming Pattern Concrete Example
Prefabs PF_ PF_[Category]_[Name] PF_PlayerRoot, PF_Crate_Medium, PF_Door_Sliding
Materials MAT_ MAT_[Surface]_[Color/Type] MAT_Concrete_Wall, MAT_Interactable_BlueGlow
Textures T_ T_[Name]_[MapType] T_MetalGrid_Albedo, T_MetalGrid_Normal
Audio Clips SND_ SND_[Action]_[Variant] SND_Push_Blast_01, SND_Pull_Hum_Loop, SND_Door_Open
Scenes None [Type]_[Number/Name] PrototypeLab.unity, Level_01.unity, MainMenu.unity

4. Version Control Hygiene & Unity Git Rules

Unity projects create thousands of temporary cache files every time a scene is opened. Never commit Unity's generated cache files to Git. Doing so inflates the repository size to gigabytes and causes impossible merge conflicts.

Folders That MUST Be Committed (Source of Truth)

  • Assets/ — All scripts, prefabs, materials, and scenes created by the team.
  • Packages/manifest.json — Unity Package Manager dependency list.
  • ProjectSettings/ — Physics layers, input actions, tags, and editor configurations.
  • .gitignore — Root repository exclusion rules.

Folders That MUST Be Ignored (Never Commit)

  • Library/ — Unity's local asset cache (regenerated automatically on each computer).
  • Temp/ — Runtime temporary build files.
  • Obj/ & Build/ — Compiled C# assemblies and standalone game builds.
  • Logs/ & MemoryCaptures/ — Editor diagnostic output.
  • .vs/ & .idea/ — Visual Studio / Rider IDE user settings.
Gold Standard Team Collaboration Rule:

Never allow two team members to edit the same .unity scene file at the same time. Unity scene files are massive YAML files that cannot be merged with Git. Instead, work inside separate scenes (e.g. Person 1 in PrototypeLab, Person 3 in Level_01), and package all gameplay objects into Prefabs before sharing them.
